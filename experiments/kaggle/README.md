# Kaggle execution package (compute environment, not a dataset mirror)

These notebooks run the repository's gated CLI at an exact commit inside a **private Kaggle notebook session**. They are generated by `scripts/remote/make_kaggle_notebooks.py`; do not hand-edit the `.ipynb` files.

| Notebook | Job | Downloads data? | Gate |
|---|---|---|---|
| `00_environment_probe.ipynb` | environment probe and transfer-client test | **No** | none |
| `01_b2_acquisition.ipynb` | JOB-01: B2 official acquisition | yes, into ephemeral session storage | `acquire_data` (B1 PASSED, B2 AUTHORIZED) |
| `02_training_job.ipynb` | JOB-02..07: one arm/seed training run, resumable | re-download + `verify-inventory` | `train_main` (B1–B12, D1–D6) |
| `03_evaluation_job.ipynb` | JOB-08: evaluation | re-download + `verify-inventory` | C gates and the `eval-v1` tag |
| `04_export_results.ipynb` | collect provenance-checked result artifacts | no | none |

Rules:

- Raw data stay in `WORK=/tmp/brats` and disappear with the session.
- Never save raw data as notebook output, never create a Kaggle Dataset with BraTS data, and never share session outputs that contain data.
- Only records, reports and checkpoints go to `/kaggle/working`. The owner downloads them and commits evidence from the owner's checkout. Gate transitions happen there, never in the session.
- Enable GPU and Internet in the notebook settings.
- Never type credentials into a cell. If the repository is private, use a Kaggle Secret.
- Kaggle's session and quota limits (`configs/compute/remote_compute.yaml`) are planning values. The probe measures the hardware; the account shows the quota.
